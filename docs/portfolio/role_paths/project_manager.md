# Project / Programme Manager path — MarginLadder

## Recruiter takeaway

A staged delivery plan for a hypothetical plant: what ships in which order, who decides at each gate, how success is measured, and what stops the programme. It is a plan and a build, not a run project. No client, sponsor or team existed.

## 5-minute inspection route

1. `docs/strategy/rollout_30_60_90.md`: phases, week-by-week actions, done-when conditions and decision rights.
2. `docs/product/pilot_design.md`: pre-registered hypotheses, baseline, guardrails and sample sizes.
3. `docs/product/roadmap.md` and `docs/product/decision_log.md`: sequencing and 13 recorded decisions.
4. `docs/finance/decision_bridge.md`: the gates that release the next payment or stop the work.
5. `docs/ba/uat_scripts.md`: 12 acceptance scripts written for a frozen build.

## Demonstrated competencies

- Scope control: Early Release first, full costing build only after Gate 3 evidence.
- Stage gates tied to money: second payment only if the register is in daily use.
- Risk handling: capacity, price parity, adoption and data-quality risks each have a test.
- Measurement discipline: baseline, denominator, guardrails and stop rules written before data exists.
- Stakeholder mapping across estimator, estimation head, sales, plant and finance.

## 60-second walkthrough

"I did not plan a big build. I planned a 30-60-90 programme with three gates. Week 1 would trace ten recent RFQs and asks the plant one capacity question. If costing is not the bottleneck, the full build stops there. If it is, the costing screen follows, and the second payment depends on the register being in daily use. Each gate has an owner and a written pass rule, and the pilot rules were fixed before any data."

## Honest claim boundary

Say "designed and documented" for the plan, gates and UAT scripts. Do not say you led a team, ran a pilot, hit a milestone or delivered to a client.
